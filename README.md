# Environment Setup

Python package dependencies required for this workflow are listed in:

`chemprop_requirements.txt`

The code was developed and tested using **Python 3.13.1**.

## 1. Install Conda

Install Miniconda, Miniforge, or another Conda-compatible distribution if Conda is not already available on your system.

## 2. Create a New Environment

Create a new Conda environment using Python 3.13.1:

```bash
conda create -n almanuscript_env python=3.13.1 -y
```

Activate the environment:

```bash
conda activate almanuscript_env
```

## 3. Install Python Dependencies

From the root directory of this repository, install the required Python packages with:

```bash
pip install -r chemprop_requirements.txt
```

The package versions in `chemprop_requirements.txt` correspond to the environment used for this workflow.


## GPU Support

Some components of the workflow may use GPU acceleration.

The original computational environment used **CUDA 12.8**. CUDA installation and compatibility depend on the user's operating system, GPU hardware, and PyTorch installation, so CUDA should be configured according to the requirements of the local system.

## Expected Outputs

The repository contains two demonstration workflows:

1. the real-time active learning workflow (Figure 4), which produces the high-throughput screening plate ranking for the demonstration data
2. the active learning simulation workflow (Figure 2)

### Real-Time Active Learning Outputs

After successful completion of the real-time active learning demo, the specified output directory should contain:

```text
real_time_AL_output/
├── checkpoints/
├── model_predictions/
│   └── ecoli_pcontrol.csv
├── ecoli_filt.csv
├── ecoli_filt.npz
├── remaining_unscreened_molecules.csv
├── remaining_unscreened_molecules_filt.csv
├── remaining_unscreened_molecules_filt.npz
├── rationales.csv
└── scores.csv
```

#### Filtered Input Data

* `ecoli_filt.csv` — filtered E. coli training data containing compounds with successfully computed molecular features.
* `ecoli_filt.npz` — molecular feature arrays corresponding to the compounds in `ecoli_filt.csv`.
* `remaining_unscreened_molecules.csv` — compounds remaining after previously screened plates have been removed from the candidate pool.
* `remaining_unscreened_molecules_filt.csv` — remaining unscreened compounds for which molecular features were successfully computed.
* `remaining_unscreened_molecules_filt.npz` — molecular feature arrays corresponding to the compounds in `remaining_unscreened_molecules_filt.csv`.

#### Model Checkpoints

The `checkpoints/` directory contains the trained Chemprop ensemble and associated training metadata. A typical checkpoint directory contains:

```text
checkpoints/
├── args.json
├── fold_0/
├── fold_1/
├── fold_2/
├── fold_3/
├── fold_4/
├── quiet.log
├── test_scores.csv
└── verbose.log
```

The `fold_0` through `fold_4` directories contain the individual trained models comprising the Chemprop ensemble.

#### Model Predictions

The `model_predictions/` directory contains predictions generated by the trained model:

```text
model_predictions/
└── ecoli_pcontrol.csv
```

#### Molecular Rationales

The output directory also contains:

```text
rationales.csv
```

This file contains the inferred molecular rationales used by the plate ranking procedure.

#### Batch-Selection Scores

The batch-selection demo produces:

```text
scores.csv
```

This file contains plate-level scores and rankings used to prioritize plates for subsequent screening. It includes the component selection metrics and the final `overall_rank`, with the highest-priority plates appearing first.

## Active Learning Simulation Outputs

The active learning simulation writes results into a directory organized by acquisition strategy and run timestamp. For example:

```text
simulation_output/
└── batch_selection/
    └── 20260817_194142/
        ├── iter_01/
        ├── iter_02/
        ├── iter_03/
        ├── iter_04/
        ├── iter_05/
        ├── iter_06/
        ├── iter_07/
        ├── iter_08/
        ├── iter_09/
        ├── iter_10/
        └── run_history.csv
```

### Simulation Summary

The primary simulation output is:

```text
run_history.csv
```

`run_history.csv` provides the iteration-level summary of the active learning simulation, including the selected plates, training-set size, holdout performance metrics, percentage of hits screened, and acquisition strategy for each iteration.

### Iteration-Level Outputs

Users who want more detailed information can inspect the individual iteration directories:

```text
iter_01/
iter_02/
...
iter_10/
```

Each iteration contains the files generated during that acquisition round, including holdout predictions and the model trained at that stage.

A typical model directory within an iteration has the following structure:

```text
iter_08/
└── model/
    ├── args.json
    ├── fold_0/
    ├── predict_input.csv
    ├── quiet.log
    ├── test_scores.csv
    ├── train.csv
    └── verbose.log
```

These files provide more detailed information about the model and data used at a specific active learning iteration:

* `train.csv` — training set available at that iteration.
* `predict_input.csv` — molecules supplied to the model for prediction.
* `fold_0/` — trained Chemprop model files.
* `args.json` — model and training configuration.
* `test_scores.csv` — recorded model evaluation scores.
* `quiet.log` and `verbose.log` — training logs.

## Expected run times

Runtimes may vary depending on hardware. The simulation should take ~28 hours and the real time AL workflows should conservatively finish within 5 days using the recommended hardware indicated in the scripts. Installing the dependencies for software implementation should take <2 hours.
