# Environment Setup

Python package dependencies required for this workflow are listed in:

`chemprop_requirements.txt`

The code was developed and tested using **Python 3.13.1**.

## 1. Install Conda

Install Miniconda, Miniforge, or another Conda-compatible distribution if Conda is not already available on your system.

## 2. Create a New Environment

Create a new Conda environment using Python 3.13.1:

```bash
conda create -n almanuscript_env python=3.13.1 -y
```

Activate the environment:

```bash
conda activate almanuscript_env
```

## 3. Install Python Dependencies

From the root directory of this repository, install the required Python packages with:

```bash
pip install -r chemprop_requirements.txt
```

The package versions in `chemprop_requirements.txt` correspond to the environment used for this workflow.


## GPU Support

Some components of the workflow may use GPU acceleration.

The original computational environment used **CUDA 12.8**. CUDA installation and compatibility depend on the user's operating system, GPU hardware, and PyTorch installation, so CUDA should be configured according to the requirements of the local system.

The demonstration workflow was developed and tested in an HPC environment (Operating system: Red Hat Enterprise Linux (RHEL) 9.8). Commands and shell script formatting should be adjusted as needed.

## Expected Outputs

After successful completion of the real-time active learning demo, the specified output directory should contain the following files and directories:

```text
real_time_AL_output/
├── checkpoints/
├── model_predictions/
│   └── ecoli_pcontrol.csv
├── ecoli_filt.csv
├── ecoli_filt.npz
├── remaining_unscreened_molecules.csv
├── remaining_unscreened_molecules_filt.csv
├── remaining_unscreened_molecules_filt.npz
├── rationales.csv
└── scores.csv
```

### Filtered Input Data

* `ecoli_filt.csv` — filtered E. coli training data containing compounds with successfully computed molecular features.
* `ecoli_filt.npz` — molecular feature arrays corresponding to the compounds in `ecoli_filt.csv`.
* `remaining_unscreened_molecules.csv` — compounds remaining after previously screened plates have been removed from the candidate pool.
* `remaining_unscreened_molecules_filt.csv` — remaining unscreened compounds for which molecular features were successfully computed.
* `remaining_unscreened_molecules_filt.npz` — molecular feature arrays corresponding to the compounds in `remaining_unscreened_molecules_filt.csv`.

### Model Checkpoints

The `checkpoints/` directory contains the trained Chemprop ensemble and associated training metadata. A typical checkpoint directory contains:

```text
checkpoints/
├── args.json
├── fold_0/
├── fold_1/
├── fold_2/
├── fold_3/
├── fold_4/
├── quiet.log
├── test_scores.csv
└── verbose.log
```

The `fold_0` through `fold_4` directories contain the individual trained models comprising the Chemprop ensemble.

Additional files include:

* `args.json` — model and training configuration.
* `test_scores.csv` — recorded model evaluation scores.
* `quiet.log` and `verbose.log` — training logs.

### Model Predictions

The `model_predictions/` directory contains predictions generated by the trained model. For the E. coli demonstration, the expected prediction file is:

```text
model_predictions/
└── ecoli_pcontrol.csv
```

### Molecular Rationales

The output directory should also contain:

```text
rationales.csv
```

This file contains the molecular rationales used by the batch-selection procedure.

### Batch-Selection Scores

The batch-selection demo produces:

```text
scores.csv
```

This file contains plate-level scores and rankings used to prioritize plates for subsequent screening.

For each plate, the output includes quantities such as:

* predicted number of potentially inhibitory compounds;
* number of novel predicted hits;
* mean novelty of predicted non-hits;
* number of unique molecular rationales;
* number of within-plate chemical clusters;
* rank for each individual selection criterion; and
* the final `overall_rank`.

The rows in `scores.csv` are ordered by `overall_rank`, with the highest-priority plates appearing first.

The exact location of `real_time_AL_output/` is determined by the output directory supplied when running the workflow.
